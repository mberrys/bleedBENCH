# stats-auditor review — bleedBENCH v2.0

Verdict: **FAIL** — the statistical core is not freezable as written. Two independent S1 classes remain:
(a) the headline safety gate's zero-event bounds are **not cluster-robust** (nominal "95% UB ≤ 1%" is
≈2.3% under the spec's own design effect, and the "larger of exact vs bootstrap" remedy is degenerate for
zero events); (b) the sample-size arithmetic that justifies the private set and the minimum-sample table
contains a design-effect inversion and ignores the spec's own clustering and attrition. Both are fixable,
but the numbers quoted cannot be used as protocol-freeze evidence until corrected.

### Statistical observations that did not make the top-10 but matter for freeze

1. **Page-level 300-page acceptance set cannot carry the claimed 1% bound** (§3.3 L336, §7.6 L891, §10.3 L1082, DD55 L1400). 0/300 = 0.994% only if **all 300** pages are accepted; any rejection reduces n (0/200 = 1.48%, 0/150 = 1.97%). With the spec's own page-level DE of 1.11 (ICC 0.05, m = 3.25), the required n is `299×1.11 = 331` pages (0/331 = 0.90%); at DE 1.45 it is 433. The claim in §10.3 L1082 ("1,300 pages gives 325 accepted pages, enough with a small margin") is therefore false under the spec's own clustering model: `325/1.11 = 292.8 → CP UB = 1.02% > 1%`. §7.6 L891 says "needs 300 accepted pages" while §10.3 L1082 says 299 — reconcile (the minimum is 299, but a 300-page *set* has no rejection headroom).
2. **Bootstrap-with-few-clusters**: the sealed test has only 16 families on Tier A and 25 on Tier B (§3.1 L318, §3.2 L328). Percentile CIs from 16 resampled clusters are unreliable (critical values ≈ ±2.1–2.2, granularity 1/16) — the "family-bootstrap 95% CI excludes zero" leaderboard rule (§7.6 L895, R7) is procedural front-running on a 16-cluster test. Either state the cluster count next to every public CI, or require the Tier A train+eval families... (no — tiers must not be pooled) or use a t-percentile/BCa correction and report the number of clusters.
3. **R1/R2 are declared primary endpoints but are under-powered on the private dev set**: texture needs ≥55 texture pages (§10.4 L1093) but the private dev set has ~49 (§10.6 above); flat severe rate <5% with an exact UB ≤5% needs 59 flat pages zero-event (0/59 = 4.95%) — Tier C dev has 39%×975 = 380 flat pages ✓, so R2 is fine; only R1 fails. Also note the four primary endpoints (§10.5) do not include R6/R8, which are described as gates — clarify that R1–R8 is a decision rule, not a hypothesis family.
4. **The gate can be gamed at the margin**: because Gate A/B status (used in leaderboard ordering step 2) is certified on calibration and the calibration split for Tier A is public, a submitter can fit a gate to calibration until it certifies, then submit it. The sealed test will then show worse coverage/severe than calibration. The spec should rank on test-split gate performance (coverage × SystemGain at test-accepted severe) and treat calibration certification only as an eligibility screen, or hold out a certification split (see top finding #2).
5. **Severe-rate expectation vs R3 anchor**: R3 sets the safety anchor at edge_repeat's **v1 3.35%** (App. B.5), while §9.2 predicts edge_repeat severe 2–6% on the synthetic set and v2 adds LaMa to the oracle (which lowers oracle_mae → lowers the severe threshold → raises every method's severe rate vs v1). An "overall severe ≤3.35%" pass line for v2 methods is therefore not comparable to v1's number; say which oracle and which tier the 3.35% refers to in R3, or express R3 as non-inferiority to the frozen-oracle edge_repeat in the same run.
6. **Quiet protocol**: the p50 ±10% minimum (100 tiles, 3 reps, §10.4 L1098/§11.3 L1141) is enough for a 10%-CV timing (SE of the median ≈ 1.25·10%/√100 = 1.25%); the "second day, larger p50 if >10%" rule (§11.3 L1144) is a max of two runs — fine, but state that H1/H2 use the *larger* run's p50/p90, and that the "100 warm" wording in §10.4 means 100 timed (not warm-up) tiles.
7. **§2.3 consequence 4 / §2.5**: "26% more strip" (48/38 = 1.263) and `regen_trim_px = 0 for L ≤ 16` are numerically consistent; the 8/16-latent-cell claims check out (48 = 3×16). No finding.
8. **§9.1 oracle**: "six classical + LaMa = seven" matches BL3–BL8 (six classical) + BL9; `edge_repeat` is not in the oracle set, which is consistent with the 9.00 → 8.58 oracle MAE and the 2.5–2.9 headroom. No finding.
